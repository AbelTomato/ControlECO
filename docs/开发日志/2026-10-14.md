## 时间未记录 · 入账模型改为"先直接入账"：入账提醒=已记一笔 / 悬浮卡=改与删（v0.5.4-beta）


### 需求（用户定稿的三条语义修正）

1. **入账提醒不是"去待确认列表处理"的入口**：它只是提醒用户"记了一笔账"——捕获即先入账，通知告知结果；
2. 三个开关下的小字说明全部删除（设置页与权限页的开关行只留标题与开关）；
3. **悬浮窗入账改为"先入账、后确认"**：捕获即直接落账，用户点「忽略」再删除这笔、改了字段则同步修改——
   这样悬浮窗没正常弹出时，账单不会丢，而是默认入账。

### 关键设计决策

- **先直接入账**（`enterEntry`，三种入账方式共用）：任一开关（入账提醒/悬浮窗入账/自动入账）开启，
  捕获即按推测分类/账户落账（条目以 AUTO 留在合并池供后续富化）。**三个全关才退回待确认队列**
  （保留"完全手动确认"的用法；金额缺失、无可推测分类、±60s 重复预检命中同样回落待确认，不丢单）。
- **悬浮卡两种模式**（`ConfirmCardWindow.showConfirm(alreadyEntered=…)`）：
  - 已入账模式（悬浮窗入账的常态）：标题"已记入一笔支出"，「保存」= 同步修改（细条可撤销整笔）、
    关掉卡片（✕/点空白/60 秒无操作）= 保留这笔并同步改过的字段（没改就不写库）、「忽略」= 删除这笔；
  - 待确认模式（兜底条目）：保持旧语义（关闭即入账 / 忽略丢弃）。
- **入账提醒通知**：`已记入一笔支出 ¥X · 商家 · 点击可修改`，点击进该笔编辑页，附「撤销」一键删除
  （新增 `CaptureActionReceiver.ACTION_UNDO`，与卡片「忽略」同一删除路径 `PendingActions.undoEntered`）。
  卡片在展示时抑制通知（卡片本身就是交互入口）。
- **编辑同步**（`PendingActions.updateEntered`）：卡内当前值写回交易 + AUTO 条目（后续富化基准），
  并学习商户归类（与确认入账同一口径）；金额被清空/分类账户缺失时保持原记录不动
  （`canSyncOverlayEdits` 纯函数 + 单测）。
- 设置页三个开关只剩标题；权限页「悬浮窗入账」开关行同样去掉小字，教程补一句
  "卡片打开时这笔账已经记好：改完关掉即同步；点「忽略」删除这笔"。

### 验证

- 单测：**349 例 0 失败**（新增 `directEntryEnabled` 4 例、`canSyncOverlayEdits`/edited 快照 4 例）。
- 构建：assembleDebug / assembleRelease 通过（versionCode=28 / v0.5.4-beta）。
- 待真机验收：只开悬浮窗入账付一笔 → 卡片标题"已记入一笔支出"，改分类/金额后关掉卡片 → 账目同步更新；
  点「忽略」→ 该笔被删除；把悬浮窗权限关掉再看 → 账照样记好，收到「已记入一笔账」通知，点通知进编辑页、
  通知上的「撤销」可删除；三个开关全关 → 捕获进待确认队列不自动入账。


## 时间未记录 · 三处修复：入账方式默认与启动校正 / 悬浮卡不弹 / 首页消息预览误捕获（v0.5.3-beta）


### 问题一：首次进入时「自动入账」与「悬浮窗入账」同时为开（与互斥说明不符）

**根因**：互斥只在"切换开关"时执行。旧版本（单个「自动入账」开关时期）用户开过自动入账，
机内 prefs 留下 `auto_entry_enabled=true`；升级后悬浮窗入账的默认值是开（prefs 未写入该键）——
首读两个都为开，捕获走自动入账路径（自动入账先于弹卡判定），**悬浮卡于是永远不弹**。

**修复**：默认取向定稿为**自动入账开、悬浮窗入账关**；启动时做一次校正（纯函数 `entryModeFix`）：
两个都开时自动入账优先、关掉悬浮窗；例外：悬浮窗是**显式**开启且自动入账从未设置过 →
尊重悬浮窗模式（写入 auto=false），不夺走用户的选择。

### 问题二：只开「悬浮窗入账」时，支付宝付款后卡片不弹（通知正常发送）

**排查结论**（逐条核对弹卡判定路径）：卡片判定原本是"预检 → 3 秒延迟 → 复检"，
而**预检也要求"前台应用 = 捕获来源"**——支付完成瞬间的前台窗口经常还是系统弹层
（支付保护/安全键盘，`com.android.systemui`、`com.miui.securitycenter` 等）或用户已回到桌面，
预检直接否决，卡片根本走不到 3 秒后的复检；此外同笔被第二通道捕获（页面合并/跨通道归并）时
只刷新已展示的卡片、不会补弹。

**修复**：
1. 预检只判"硬条件"（开关/权限/本应用前台/屏幕），前台匹配留到 3 秒延迟后的复检；
2. 系统弹层/桌面占据前台时按"判不出"处理（纯函数 `isSystemSurface`），不再误判成"用户已切走"；
3. 富化路径补一次"卡片优先"（`retryCardIfNoCard`）：首次尝试被当时的系统弹层挡掉后，
   同笔的第二次捕获（页面/银行）会重新尝试弹卡，成功则撤销早先的横幅通知（同一笔不重复打扰）；
4. 排查可见化：每次判定结果写进日志，并在 权限页「悬浮窗入账」下显示
   「最近一次捕获未弹卡：<原因>」——不用抓 logcat 就能定位。

### 问题三：打开支付宝首页（含历史账单预览）也被捕获成一笔

**实测样本**（2026-10-14）：首页"最近消息"卡片里挂着"淘宝闪购极速版 付款成功￥21.00  1小时前"，
命中支付页锚点 → 被记成 ¥21.00 支出（counterparty 还被兜底成"最近消息"）。

**修复**：新增**页面形状闸门**（支出/收入两条路径共用，任一命中即拒，`nonResultPageReason`）：
1. 消息中心用语（最近消息/条新消息/消息盒子/…）；
2. 首页宫格入口词 ≥3 个（扫一扫/收付款/卡包/…）或微信主界面底栏（通讯录+发现）；
3. 锚点（或前后 2 个节点）带相对时间（"1小时前"）——消息预览的签名；
4. 富页面 + 锚点埋深：节点 ≥30 且锚点下标 >8（支付完成页信息少、锚点必然靠前；反过来
   "锚点靠前的富页面"仍然照常解析，不误伤结果页下方的推荐位）。
