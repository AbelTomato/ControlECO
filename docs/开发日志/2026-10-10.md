## 时间未记录 · 修图标：自适应图标前景层不能留空（MIUI 回落系统默认图）


### 现象与定位

换新图标后装机，桌面/应用信息页显示的都是**系统默认图标**（蓝格机器人）。Logcat 给出铁证：

```
W PackageManager: Failure retrieving resources for com.controlexo.app:
    Drawable com.controlexo.app:mipmap/ic_launcher with resource ID #0x7f080000
```

（异常消息即 `Resources.NotFoundException`——`AdaptiveIconDrawable` 解包整层失败，系统回落到默认图。）

- 第一版结构：`background = 图案 PNG`、`foreground = 空 vector`（想让背景层独占图案，躲开启动器的前景视差）。
  **空 vector 就是元凶**——AOSP 的层解包对它不抛错，但 MIUI 的图标加载链路会整层失败。
- 另一个坑：**MIUI 的图标缓存按"包名 + 版本"记**，同版本号覆盖安装不会失效——
  改完结构后 `install -r` 甚至重启启动器进程，应用信息页仍显示旧的默认图；
  `uninstall` + 重新 `install` 才刷新（所以修复版顺带把版本号 +1，方便装机侧缓存失效）。

### 修复

- `mipmap-anydpi-v26/ic_launcher(.round).xml` 改为常规结构：**色底（`@color/ic_launcher_background`，
  与图案外圈同色 `#077A41`）+ 图案 PNG 作前景**；删掉空的 `ic_launcher_foreground.xml`。
  图案外圈本就是同一深绿，边框处即使启动器做前景视差也看不出位移。
- 版本 v0.4.3-beta → **v0.4.4-beta**（versionCode 6 → 7），废弃有缺陷的 0.4.3 构建。

### 验证

- 干净安装后 `aapt2` 核对 `versionCode=7 / versionName=0.4.4-beta`；装机截图：**应用信息页显示绿色钱包 ECO 图标**、
  名称「我ECO」，Logcat 里 `Failure retrieving resources` 归零。

## 时间未记录 · 第十轮反馈：捕获页面优先、自动入账、启动权限自检、记一笔紧凑化


### 需求与实现

1. **捕获优先级：通知与页面同时捕获一笔（10s 内）时页面信息优先**。
   页面侧带商户/支付方式，信息更全——两条通道的合并规则抽成纯函数模块 `capture/CaptureMerge.kt`：
   - **同一笔判定**：同包名 + 同方向 + 两次**捕获时刻**相差 ≤ `SAME_ORDER_WINDOW_MS = 10s`
     （原来用"交易时间的 ±1 分钟分钟桶"，页面上的时间常常只有分钟精度，跨分钟会误配；
     改成捕获时刻后两通道对齐更准）。金额相同直接命中；金额不同时（通知误解析历史：支付宝 ¥1.00）
     **只有"页面侧发起合并且窗口内候选唯一"**才认作同笔——页面金额更可信；
     通知侧发起时严格比金额（同 App 内 10s 内两笔金额不同的付款不能被并成一笔、丢记录）。
   - **合并方向**：通知先到时，页面**覆盖**金额/时间/商户/备注/规则名（原来是"只追加富化"，
     通知侧那句"付款成功"会顶在前面）；页面没有的字段保留通知侧原值；支付方式并入备注。
     页面先到时通知侧照旧丢弃（页面信息更全，没有回填价值）。
   - 配套修 `deletePendingFor`：合并会改写通知侧条目的金额，去重键里的金额段就不再等于当前值，
     所以确认/忽略时按"同笔家族"（同包名 + 同方向 + 分钟 ±1）清理，避免留下第二条待确认。
2. **自动入账**（设置 → 自动记账 → 「自动入账」，默认关）。
   - 识别到付款后按**推测分类**（该类型的「其他」，缺省第一个）+ **推测账户**（按来源包名：微信/支付宝/银行）
     直接落账，不进待确认、不弹悬浮卡；`CaptureDefaults` 把这套推测抽出来，待确认弹窗的默认值也走同一份。
   - 落账后仍**留一条 `status = AUTO` 的合并记录**：页面通道随后捕获同笔时，把商户/支付方式
     **回填到已入账的那笔交易**（`updateCapturedByExternalId`，按 externalId = `NTF:去重键` 定位）。
   - 发一条「已自动入账」横幅，点击**直达该笔编辑页**（新增追加路由 `edit/{txId}`；既有 `pending` /
     `refundLink` 两个路由名是契约，没动）。
   - 没有可用分类/账户或写入失败 → 回落到原待确认流程；UNIQUE 冲突（重复通知/双通道）按"已入账"处理。
   - `AUTO` 记录只在合并窗口里有意义，`cleanup()` 每日清理（`PendingStatus` 按名字存文本，
     加枚举值不需要迁移；待确认列表的查询都带 `status = 'PENDING'`，不会漏出来）。
3. **打开软件时的权限自检**：`capture/CapturePermissions.kt` 检查四项——
   通知监听 / 无障碍 / 悬浮窗 / 通知权限。**只提醒"功能开着但没授权"的项**（用户主动关掉的开关不唠叨），
   每次冷启动最多弹一次（Activity 重建不重弹），且从捕获通知直接进入 App 时不打扰处理动线；
   去系统设置授权后返回会重查、补齐即自动收起。弹窗文案极简：
   「自动记账尚未就绪 / 缺少 N 项：通知监听、无障碍 / 去开启 · 稍后」。
4. **「记一笔」紧凑化**（窗口不够用导致数字键盘被挤出屏幕）：
   - **分类选择改折叠条**：收起时只显示当前选中分类名 + 展开箭头，点击展开全部（限高 96dp 可滚动），
     选完自动收起——不再把十几个分类铺满屏幕；
   - 字号/控件整体调小：金额 `displayMedium → headlineMedium`、键盘 `24sp/56dp → 20sp/46dp`、
     按钮 `52dp → 44dp`、说明文字 `bodySmall → labelSmall`；
   - 「更多细节」区放进 `weight(1f)` + 可滚动的列（展开时挤占剩余空间、超出可滑），
     数字键盘与「记一笔」按钮始终在屏内。

### 踩坑

- 合并改写 dedupKey 会撞唯一索引：**没有**把待确认条目的 dedupKey 改成页面侧的去重键
  （同一分钟若已存在同键条目，UPDATE 会直接抛 UNIQUE 冲突、整段合并失败），
  改为"键不动 + 清理按家族匹配"，既保住合并又不引入新的失败面。
- "金额不同也算同笔"这条规则只对**页面侧**开放：通知侧发起时如果也放宽，
  同 App 内 10s 内两笔金额不同的付款会被并成一条（第二条被当重复丢弃）——数据损失比多一条待确认严重。
- 自动入账的 externalId 必须用**合并前**读到的 dedupKey 去拼（AUTO 记录后续可能被改写字段），
  否则回填会找不到那笔交易。

## 时间未记录 · 第九轮反馈：本日剩余只算支出、圆环与图标同色、调色板收 8 色、色环自定义


### 需求与实现

1. **「本日剩余」只算支出**：预算看的是花销，所以**工资/红包这类收入不再参与**
   （拿到收入不会让今天的额度变多），但**退款要正常算回来**（钱退回来了 = 当天没花）。
   今日口径改为 `今日支出 − 今日退款到账`（VM 侧 `homeTodayNetSpent`：`observeTypeTotals` 取支出 +
   `observeRefundIncomeTotal` 取退款，两条查询和月度"现金净流出"同源）。
2. **统计页圆环颜色与分类图标同步**：新增 `sliceColorsOf`（ui/stats/SliceColors.kt）——
   - 图标**自定义过颜色**（`GLYPH:名字:RRGGBB` / "只改颜色"的 `GLYPH::RRGGBB`）→ 圆环直接用那个颜色；
   - 图标是**内置图形**（默认取形或选了图形没改色）→ 用按分类名的自动取色，和账单列表里图标一致；
   - 图标是 **emoji / 相册图片**（本身没有颜色）→ 交给 `ringColors` 从调色板里挑
     "离所有已用颜色最远"的一个（CIELAB ΔE 最远点贪心，阈值 `RING_MIN_DELTA = 26`）。
   原来的 `ringBoost`（给圆环单独提饱和）随之删掉：同步优先，颜色就是图标的颜色。
3. **调色板 16 色 → 8 色**（明暗两套）：色相大致等间隔（红/橙/黄/绿/青绿/蓝/紫/玫红），
   最小 ΔE 从 16 色时的 ~23 拉到 **34.6**，一眼能分；想要更细的区分就用下面的自定义色环。
4. **自定义颜色：色环弹窗**（ui/common/ColorWheel.kt，全自绘）：
   - 色环 = 扫描渐变描的圆环（0° 在 3 点方向、顺时针），点按/拖动取色相；
   - 内部方块 = 横向"白 → 纯色相" + 纵向"透明 → 黑"，点按/拖动取饱和度与明度；
   - 十六进制（`#RRGGBB`）与 R/G/B 三个输入框与色环**双向同步**；通道超范围标红不生效；
   - 色板最后加一个"自定义"色块：没自定义时显示迷你色轮，自定义后显示当前色并高亮选中。

### 踩坑（实机 debug）

### 实机排查（Xiaomi 2602BRT18C，adb 注入仍被 MIUI 拦，本轮靠临时源码补丁 + logcat 取数）

滑动条"闪动 + 不跟手"是两个独立的真因，都是打日志量出来的：

1. **被钉住的 sticky 日期头被当成"第一个可见项"**。日志原文：
   `vis=2:o0:s172 6:o0:s243 7:o309:s243 ...`——钉住的 10月8日 头（index 2）和真正在顶部的
   第 6 项 offset 都是 0，且钉住的那项排在 `visibleItemsInfo` 最前面。原实现用第一个可见项
   算滚动量，于是拇指从第 3 项滚到第 18 项都几乎不动。改成**从最后一个可见项倒推**
   （`Σ(它之前的项高) − 它的 offset`），位置才跟着内容走、并能真正到底。
2. **拇指长度抖动**：高度估算原先只看可见项的平均，一个日期头滚进/滚出就会让平均高度跳一下；
   改成按 index 记实测高度、没见过的用已测平均补。修复前后实测：201 → 298px（会跳）
   ⇒ 302 → 295 → 296px（稳定 2% 内）。
   附带两个首帧问题：还没测到任何项时不能硬猜平均高度（会画出一根长度离谱的拇指，下一帧再跳回
   正常 = 刚打开页面时的那次闪动），改成先不画；而"补画"必须靠一个版本号触发重组，否则静止在
   列表顶部时永远等不到下一次重组，拇指干脆不出现（这处是第二遍走查才发现的）。
3. **拖动比例改为按下时定死**：原来每帧重算，拖动中列表在滚、比例跟着变，拇指追不上手指。

滚动卡顿：`Money.grouped` 每次调用都 new 一个 `DecimalFormat("#,##0")`——账单行/日期头/统计
每帧都在格式化金额，构造 + 解析模式的开销是实打实的卡顿源。改成手写千分位
（`MoneyTest` 补了 8 个档位断言，含 `Long.MAX_VALUE`），另外账单行的时间字符串、日期头的当日
汇总都用 `remember` 缓存，滚动时不再重复做日期转换与求和。

### 统计页

- **圆环常驻屏幕上方**：页面从 `Column + verticalScroll` 换成 `LazyColumn`，分类圆环做
  `stickyHeader`；图例在下面滚，圆环钉在顶部——点图例 = 点圆环，两边必须同时在视野里。
  "点空白取消选中"的手势跟着挂到 LazyColumn 上；底部标签回到顶部改用 `listState`。
- **两侧数字跟随选中项**（用户口径）：未选中 = 总花费 / 总预算；选中 = 该分类的花费 / 预算，
  分类名显示在左上角（费用金额上方）。删掉「花费」「预算」标签与上方读数行（信息已由两侧列承担，
  顺带解决"文字顶到上方"），金额换 `formatYuanCompact`（与首页同一套 K/M/B 进位规则）、
  字号降一档，与圆环左右各留 12dp 后整体垂直居中。

- 筛选按钮：原"循环按钮 + 圆箭头"读不出有哪几个选项，改成通用的三段式 `SegmentedSwitch`
  （与月/年切换同一套外观，`PeriodSwitch` 收敛为它的薄封装，结余卡的自定义配色照旧可传）。
