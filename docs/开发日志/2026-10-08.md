# 开发日志 2026-10-08


## 时间未记录 · 卡面图片"先闪默认背景"根治：改由 ViewModel 启动即解码（缩略图 → 全尺寸）


### 需求（用户反馈）

实测悬浮卡片的背景仍然会先显示一下默认背景，再闪回设置好的图片。

### 根因

上一版虽然把"平均色打底"加上了，但有两个漏洞：
1. **只在账单页第一次组合时才触发解码** —— 用户切到账单页时图片还没解码，先画的就是默认几何背景；ViewModel 里没有预热。
2. **已存在的图片没有平均色**：`card_image_color / card_image_luminance` 是这版新加的 key，用户那张照片是在此之前导入的，prefs 里没有 → 占位色为 null → 又落回默认几何背景。

### 实现

1. **把卡面图片加载搬进数据层**（新 `data/CardImage.kt`：`CardImage` + `CardImageLoader.decode/averageColor/meanLuminance` + `importCardImage`）：ViewModel 拥有 `cardImage: StateFlow<CardImage?>`。
2. **启动即解码，两级出图**：VM 初始化（和换图时）就在 IO 线程解码——先按 80px 目标尺寸解码出**超小缩略图**（JPEG 支持 DCT 缩放，通常几毫秒），马上可画且能算出平均色/亮度；再解正常尺寸（长边 ≤1600）替换。用户切到账单页时通常已经是全尺寸图，最差也是缩略图。
3. **回填**：解码时若发现 prefs 里没有平均色/亮度（老数据），顺手写入一次 —— 实测用户那张照片的 prefs 已补上 `card_image_color` 与 `card_image_luminance=0.118`（对应深色图，走深底白字）。
4. **默认几何背景只属于"没设图"**：绘制分支改为 `真实图 → 缩略图 → 持久化平均色 → （设了图但都没就绪）留白 → 无图才画自绘背景`，从结构上消除"先默认再换图"。
5. `BalanceCard` 瘦身 329 行 → 只负责画与排版，加载逻辑全部移出。

### 验证

- `:app:assembleDebug :app:testDebugUnitTest` 通过（96 tests，0 failures）。
- 实机冷启动（force-stop → start）：启动动画结束后即为全尺寸图 + 完整数据；prefs 里确认平均色/亮度已回填；顺带看到用户新记的一笔显示为 `07:11`（手动记账时间默认改成"记账时刻"这条也生效了）。
- 说明：启动瞬间的截图只能拍到系统启动动画（screencap 往返比那几十毫秒慢），"不再闪"属于结构性修复 + prefs 客观校验（回填成功）。


## 时间未记录 · 冷启动不闪：数据流改"未就绪=null"闸门 + 卡面平均色打底 + 启动预热


### 需求（用户反馈）

希望做持久缓存（杀后台冷启动也能加载缓存）；加载未完成时**什么都不要显示**——不要先出现空页面或默认页面，否则"闪一下"观感很差。

### 实现

1. **持久缓存其实已经在磁盘上**：账单/统计的数据来自本地 Room（SQLite）数据库，杀进程后仍在，冷启动就是"从缓存读"；卡面图片也已存成内部文件。真正的问题是**读出来之前 UI 先渲染了一屏"假内容"**（空列表 / 默认卡面 / 0 值统计），所以这次重点是消除中间态。
2. **数据流"未就绪 = null"**：`periodRows / periodTotals / periodCategorySums / periodRefundTotal / homeNetSpent / homeCategorySums / totalDepositCents` 的 `stateIn` 初值由 `emptyList()/0L` 改成 **null**，语义是"还没读出来"。
3. **四个页面统一闸门**：账单、统计、首页、个人页在数据为 null 时**直接 return，什么都不画**（不显示"暂无记录"空态、不显示默认卡面、不显示 0 值）。数据一到即刻整页出现——宁可短空白，也不要"先假后真"。
4. **卡面平均色打底**：导入图片时一次遍历同时算出**平均色（ARGB）与平均亮度**并持久化到 prefs；位图解码完成前，卡片用这个平均色铺满（不是默认几何背景），所以冷启动看到的不是"突然换背景"，而是"同色 → 图片"的平滑过渡。清空背景时一并清掉这两个值。
5. **启动预热**：ViewModel 初始化时立刻在 IO 线程碰一次数据库（`countAll`），把 SQLite 首次打开/建连的开销与首帧并行，缩短"什么都不显示"的窗口。

### 验证

- `:app:assembleDebug :app:testDebugUnitTest` 通过（96 tests，0 failures）。
- 实机冷启动走查（`am force-stop` → `am start`）：启动瞬间的截图是**干净的空白页**（没有空列表、没有默认卡面、没有 0 值统计），数秒后的截图是完整内容（卡面照片、17 笔记录、各项金额）✓。
- 说明：这轮没有引入新的磁盘快照文件——数据本来就在 Room 里持久化，加一层 JSON 快照只能把"空白窗口"从 ~100ms 再压缩几十毫秒，代价是序列化与一致性维护；如果你希望连这几十毫秒都不要，我可以再加一层按周期缓存的快照（写入时去抖 + 启动时校验周期是否一致）。


## 时间未记录 · 卡面图片缓存（切页不再闪默认底）+ 红包缝隙改回"平行窄缝"


### 需求（用户反馈）

切页面时会先显示默认背景再加载出图片（图片没缓存）；红包 logo 的间隙被改反了（要求缩小，结果变大了）。

### 实现

1. **卡面图片缓存**：位图原本在 `produceState(key = path)` 里按需解码，切标签页时组件重建 → 初值 null → 先画默认几何背景、等 IO 解码完才出图（就是看到的"闪一下"）。新增 `CardImageCache`：**只保留最近一张**"路径 → 已解码位图 + 亮度"（进程内缓存，切页/进出页面直接命中），`produceState` 的初值改为"先从缓存取"，命中时第一帧就是图片；换图时路径变化 → 缓存自然失效 → 重新解码。内存只多留一张卡面位图（长边 ≤1600px）。
2. **红包缝隙改回小缝**：上一版把长方形整体下移（顶边 0.36 → 0.47），三角顶点与长方形之间反而空出一大片 —— 与"间隙缩小"的要求相反。这次改成**让三角的两条斜边与长方形缺口的斜边平行**：三角 (0.16,0.08)–(0.84,0.08)–(0.50,0.42)，长方形顶边从 (0.16,0.18) 沿缺口下到 (0.50,0.52) 再回到 (0.84,0.18)，两者纵向只错开 0.10s → 整条缝宽窄一致、视觉上是一个紧凑的红包（三角最长边仍等于长方形宽度）。

### 验证

- `:app:assembleDebug :app:testDebugUnitTest` 通过（96 tests，0 failures）。
- 实机截图确认：红包已是"紧凑信封 + 均匀细缝"的样子；用户自己的卡面照片（深色）走深底白字配色，收入浅绿/支出浅红清晰可读，且开场即为图片。
- 缓存属于"组件重建后第一帧就能拿到位图"的结构性修复，无法用截图拍到"不再闪"的瞬间；真机上切标签页如有残留闪烁请告知。


## 时间未记录 · 红包 logo 收敛 + 换图不刷新修复 + 背景图位置/缩放/旋转


### 需求（用户逐条反馈）

红包颜色太显眼（降饱和）、三角太大（最长边应与长方形底边同宽）且与长方形间隙缩小；悬浮卡已用相册照片后**再选别的照片不生效**（必须切回默认再选）；背景图需要能调整**位置与缩放旋转**（选完图进入调整）。

### 实现

1. **红包 logo 收敛**（`CategoryGlyph`）：配色由 #E8342A 降到 **#D2453C**（深色主题 #E88272，`festiveRed` token 两处一起改）；几何重排——倒三角上边宽 0.80→**0.68，与长方形底边等宽**，顶点落在长方形凹口正上方，三角底到长方形顶边的缝从"交叉重叠"改为约 0.03s 的窄缝。
2. **换图不刷新的根因**：导入时文件名固定 `card_bg.jpg`，而 UI 记录的是"图片路径"——路径没变 → `produceState(key = path)` 不重跑 → 卡片不重新解码（切回默认时路径变 null 才触发刷新，正好对上现象）。改为 **`card_bg_<时间戳>.jpg`**，并顺手删掉旧文件（避免文件堆积）；旧 pref 里指向 `card_bg.jpg` 的仍能正常读取。
3. **背景图调整（位置 / 缩放 / 旋转）**：
   - 新增 `data/CardTransform`（scale、offsetX/offsetY 用**卡片宽高比例**表示、rotation 角度）+ `normalized()` 夹取（0.5–4 倍、±1.5 卡宽/高、角度归一化到 0–360）+ 一行字符串序列化，存进 prefs；
   - `BalanceCard` 绘制时用 `withTransform { translate → rotate(pivot=center) }` 叠加到"居中裁剪铺满"的基准变换上；
   - 新增 `CardImageEditorDialog`：选完图**自动弹出**，单指拖动移动、双指捏合缩放、双指旋转，带「复位 / 取消 / 应用」，预览就是真实卡面尺寸与配色（所见即所得）；背景对话框里也加了「调整位置 / 缩放 / 旋转」入口，之后随时可再调。

### 验证

- `:app:assembleDebug :app:testDebugUnitTest` 通过（**96 tests**，0 failures）：新增 `CardTransformTest` 4 条（序列化往返、空值/脏数据回落默认、越界夹取、解析时同样夹取）。
- 实机走查：用户自己已选的深色照片 → 深底白字配色（收入浅绿/支出浅红清晰）；另生成浅色测试图验证浅底墨字配色与对比度；同一张图应用 scale 1.35 + 位移 + 旋转 12° 后预览正确；编辑器交互与按钮齐备。验证用的临时改动与测试图片已全部还原/删除。

## 时间未记录 · 分类 logo 细化（汉堡/红包/K线/￥）+ 卡面明暗自动适配 + 相册选择修正 + 记账时间


### 需求（用户逐条反馈）

餐饮画三层汉堡；红包画"上方倒三角 + 下方长方形顶部扣去一个倒三角"且用明亮红；理财画三根 K 线（矩形穿插竖线，高低长短各异）；工资画 ￥；logo 不要圆角方形底板；手动记账时间默认为记账时刻；日期弹窗去掉"左右滑动"提示但保留点箭头切换；"从相册选择"打开的是文件管理要改；悬浮结余卡要**自动检测背景明暗**并据此调整文字色与月/年切换配色，保证对比度 ≥ 3。

### 实现

1. **分类 logo 细化**（`CategoryGlyph.kt`）：
   - 新增四种画法：`BURGER`（上方半圆面包 + 中间夹层 + 下方圆角面包）、`RED_PACKET`（上方倒三角 + 下方矩形，矩形顶边向下凹成倒三角缺口）、`CANDLES`（三根 K 线：实体矩形 + 中间穿插竖线，高度与线长各不相同）、`YEN`（两撇 + 竖干 + 两横）；

2. **卡面明暗自动适配**（`ui/common/CardContrast.kt` + `BalanceCard.kt`）：
   - WCAG 口径：sRGB 线性化 → 相对亮度 → 对比度比值；`scrimAlphaFor()` 反算"要叠多厚的遮罩才能让文字 ≥ 3:1"（浅底叠白、深底叠黑），最多 0.9；
   - 卡面图片隔点采样（≤48×48 点）算平均亮度，>0.30 用**浅底墨字**配色、否则用**深底白字**配色（`CardTones` 两套 token：文字/次要文字/收入/支出/遮罩/月年胶囊底色-选中色-选中文字色），三处文字（结余、收入、支出）取最严格的遮罩厚度；
   - **踩坑**：首版把"自动检测"也套在默认自绘卡面上，而浅蓝渐变卡的亮度 ≈0.44 正好低于当时 0.45 的阈值 → 被判成深底、叠了 32% 黑遮罩，整张卡变成暗灰（截图一眼看出）。改为**默认卡面直接用主题配色、不叠遮罩**，自动检测只服务于自定义背景图。
3. **"从相册选择"改成系统照片选择器**：`ActivityResultContracts.OpenDocument()`（ACTION_OPEN_DOCUMENT → 文件管理）换成 `PickVisualMedia(ImageOnly)`（相册 UI）；选完在 IO 线程**拷贝并压缩到应用内部存储**（`filesDir/card_bg.jpg`，长边 ≤1600px），不再依赖 URI 授权、清缓存或原图被删都不影响。
4. **手动记账时间**：新增记录默认用 `System.currentTimeMillis()`（记的是"现在"，含时分）；若手动选了别的日期，则用该日期 + 当前时刻。编辑记录时**保留原时分**（此前编辑会把时间抹成 00:00）。
5. **日期弹窗**：删掉底部"← 左右滑动切换年份 →"提示；年份两侧加 ‹ › 圆钮，与左右滑动**同步翻页**（点箭头 = 翻到上一/下一年的月份页）。

### 验证

## 时间未记录 · 账单页悬浮结余卡（可换背景）+ 分类几何 logo + 月/年周期 + 统计同步


### 需求（用户逐条反馈）

滑条没用；账单上方改**悬浮卡片**，可自定义背景图（默认自绘几何），大字结余、右侧收入支出（不用文字，+绿 −红）；筛选改**单按钮点击循环**且不要 √；删掉"汇总为整月数据"；日期头右侧改**本日结余**（+绿 −红）；分类左侧**不要单字符号**，每个分类画几何 logo；日期切换（按钮/箭头）太丑要美化；日期弹窗要能**左右滑动切年份**；账单页可切**月结余/年结余**（统计页同理）；统计页的日期也要弹窗；账单与个人页**取消页眉**。

2. **账单页顶部悬浮结余卡**（`BalanceCard.kt`，替换页眉 + 汇总行）：
   - 左上 = 月/年 周期切换，右上 = 背景设置；大字 = 当前周期结余，右侧两行 = 收入 `+绿` / 支出 `−红`（不带文字标签）；
   - 默认背景**自绘几何**：浅蓝竖向渐变 + 右上同心圆 + 左下圆环 + 一道斜高光，全部用主题 token（onPrimaryContainer 低透明度）画，被卡片圆角裁切；

5. **单按钮循环筛选**：一个胶囊，点一下 全部 → 支出 → 收入 → 全部；不带 √（右侧是 Refresh 图标示意可切换），非"全部"时浅蓝实底表示生效中。计数文案移到同行右侧，"汇总为整月数据"删除。

## 时间未记录 · 翻转灵敏度与立体感 + 模式②环内去百分比 + K/M/B 逐档进位修正


### 需求（用户反馈）

### 实现

1. **滑动更跟手**：比例由 `90° / 45% 卡片宽` 收紧到 `90° / 30% 卡片宽`（常量 `DRAG_FULL_TURN_WIDTH_FRACTION`），同样手指位移转得更多；再加**快速甩动**通道——`VelocityTracker` 记录指尖速度，速度 ≥ 1.1 卡片宽/秒（`FLICK_WIDTHS_PER_SECOND`）即翻页，不必等角度到 45°。角度与速度都启动时按跟手旋转方向走，只有快甩才用速度方向，方向永远与手指一致。
2. **立体感（全部在 `graphicsLayer` 的 draw 阶段读值，零重组）**：翻转进度 `p = |rotationY| / 90`，随 p 变化三件事——`cameraDistance` 从 14×density 收到 6×density（越接近侧立**透视越强**，此前 14 恒定偏"平"）、整体 `scale` 收到 0.94（轻微后退）、`alpha` 降到 0.8（受光面偏离变暗）。三者叠加读起来像一张卡片翻过去，而不是平面瞬间换内容。

4. **K/M/B 逐档进位修正**：原实现按固定金额阈值（≥1 万 K、≥100 万 M、≥10 亿 B）换挡，导致 M 提前出现（如 ¥1,234,567.89 显示 ¥1.23M，而按规则 K 档显示值 1234.57 仍是 4 位、不该进位）。改为**按最终显示文本判断**：K → M → B 逐级尝试，`小数点前位数 ≤ 4` 即停档（例：¥1,234.12 原样；¥32,312.32 → ¥32.31K；¥1,000,000 → ¥1000K；¥12,345,678.9 → ¥12.35M；¥9,999,999.99 因四舍五入成 10000K 而继续进到 ¥10M）。`COMPACT_UNITS` 常量表驱动，档位与规则单一来源。

## 时间未记录 · 圆环细节重做（偏移修复/时间环/K·M·B/心跳警示）+ 模式②其他环 + 白+浅蓝主题


### 需求（用户逐条反馈）

模式②除已设预算的分类外，"其他"剩余预算与支出归为一个"其他"环（仅预览，不改账单页）；圆环颜色弧与灰轨道有偏移（bug）、圆角过于圆润改小、环内金额多时与环重叠（需缩放 + K/M/B 单位 + 间隔）；百分比前去掉"剩余"二字；模式②要浅灰轨道；提示色绿蓝红 → **绿黄红**；背景暖金 → **白色 + 浅蓝**；模式①内套一个很细的时间环（本月过了多少，与预算对照）且大环再放大；"记一笔"改短；所有超支红饱和度加高，红色数字加"心跳 + 间隔性快速轻摇"警示（剩余越少/超支越多越强越快越艳，需设上限）；模式②不再截断 4 个，弹性塞入全部。

### 实现

1. **偏移 bug 根因与修复**：`drawArc` 默认包围盒 = 整个画布，弧的中心线半径 = min/2；而轨道用 `radius = (min − stroke)/2` 绘制，二者中心线差 stroke/2 → 弧整体外偏。修复：弧改用 `topLeft = center − r、size = 2r（r = 中心线半径）`，与轨道完全同几何（模式①②都改）。
2. **圆角改小**：弧/环取消 `StrokeCap.Round` 改用默认平头（25dp 粗描边的圆头端过于圆润）。
3. **模式①（更大 + 时间环）**：环尺寸自适应 `min(可用宽×0.84, 可用高×0.58)` 夹在 200–290dp；内圈再画一条 4dp 细环 = 本月已过比例（`dayOfMonth / lengthOfMonth`，灰调），与预算进度直接对照；百分比只显示"42%"（去掉"剩余"）。
4. **金额显示（K/M/B + 自适应缩放）**：新增 `Money.formatYuanCompact`——整数部分 ≤4 位正常分组（¥1,234.12），超过 4 位进位 K/M/B，两位小数去尾零（¥32.31K / ¥10K / ¥1.23M / ¥12.35B），负数保留符号；环内金额用新 `AutoScaledText`：超出可用宽度按比例缩字号（下限 0.55×），环内文字宽度预留心跳放大余量，不与环重叠。
5. **模式②（其他环 + 弹性网格）**：
   - `buildCategoryRings` 新增"其他"聚合环：预算 = 月总预算 − 已分配分类预算；支出 = 当月总支出 − 已计入分类环的支出 → **Σ分类剩余 + 其他剩余 = 月总剩余**（与模式①口径一致，有单测守恒断言）。无任何分类预算时"其他"即全部（此时显示一句设置引导）；全部分类预算超过总预算（其他预算 ≤ 0）时不出其他环。
   - 取消 `.take(4)`：按环数选列数（≤2 一列排、3–4 两列、5–9 三列、10+ 四列），环径取 宽/高 双约束的较小者（68–124dp）自适应缩放，超长时整列可滚动——弹性容纳全部圆环。
   - 每环补浅灰轨道（hairline），与弧同几何。
6. **警示色与心跳**（`warningSeverity` 纯函数 + `Modifier.warningHeartbeat`）：
   - 档位色改 **绿（≥50%）/ 黄（20–50%，warning 琥珀）/ 红（<20%）**；红档随强度从 `critical` 向新的 `criticalAlert`（饱和度最高的警报红）插值。
   - 强度 = `(0.2 − 剩余比例) / 0.5` 夹 0..1：红档起点 0、超支 30% 封顶 1。
   - 心跳 = 缩放 1.0→(1+0.10×强度) 的脉冲，周期 1400→650ms（随强度加快），每次脉冲后留休息；摇晃 = 每 2.6s 一小段 3 次快速轻摆（幅度 ≤2.2°）——上限即"防止过度动画"。
   - 应用：模式①环内金额+百分比块、超支大字；模式②每环金额+百分比块；模式③本月已花（红档）与负总存款。连续动画只在 draw 阶段读取（graphicsLayer），零重组；系统"减少动画"时不播放。
   - `critical` 本体也提高饱和度（浅色 0xFFA5402C→0xFFC1352B，深色 0xFFE9886F→0xFFF07C64），error 色同步。
7. **主题：白 + 浅蓝**：浅色 background/surface 纯白，容器/描线/次级色全部改为冷蓝灰（surfaceContainer 0xFFF3F7FB、hairline 0xFFE3EAF1、onSurface 0xFF1B2430 等）；深色套改为冷底（0xFF12161C/0xFF171C23）；分类调色板替换掉暖金/驼色系为冷调八色。
8. **"记一笔"改短**：悬浮胶囊文案改为"记账"（账单空态提示同步）。

### 验证

- `:app:assembleDebug :app:testDebugUnitTest` 通过（84 tests，0 failures；新增 `formatYuanCompact` 2 例、环测试扩至 10 例含其他环/守恒/不截断/警示强度）。
- 验收 grep：`Color(0x` 仅 Theme.kt（FloatingConfirmWindow 为采集层历史暗窗）；`Tone.MID` 映射 warning（黄）。
- 真机走查待装机：环大小/时间环细度/心跳幅度与频率等参数集中在 `HomeScreen.kt`（环尺寸公式、`warningHeartbeat` 的 0.10/650–1400ms/2.2°）与 `Theme.kt`（critical/criticalAlert）。

### 待观察

- 心跳与摇晃并发运行的元素最多为模式②的 6 个环（每个 1 个 graphicsLayer 变换）——若低端机仍感负担，可只保留心跳、去掉摇晃。


## 时间未记录 · 首页三模式预览（点击弹动/滑动切换）+ 悬浮"记一笔"胶囊 + 分类月预算


### 需求（用户提供参考图 + 修正意见）

首页通过**点击中心或左右滑动**切换三种预览模式：①总剩余预算（中心大圆环 + 环下方大字"本日剩余"）；②分类剩余预算（多环）；③已花费金额与总存款（中央大字、无环）。首页文件尽量少；重点用**数字与颜色**强调。首页与账单页的"记一笔"改为**填充色悬浮按钮（带动效）**。切换动效：点击=弹动、滑动=跟手滑动；颜色变化要有过渡提醒。参考图排版，但自行美化不自毁主体。用户特别指出参考图模式②不可取——**要单纯环形：文字和剩余额在环内、环无背景色/无轨道、圆环稍粗**。

### 实现

1. **三模式 HorizontalPager**（`ui/home/HomeScreen.kt` 单文件，`androidx.compose.foundation.pager`）：
   - 模式①：232dp 大环、25dp 粗描边（浅色轨道 + 剩余比例弧，剩余≤0 整环红），环内「本月还可以花 / 金额 / 剩余 X%」；环下方「本日剩余」大字（超支时改「本月已超支」红字）。
   - 模式②：**无轨道、无卡片底色的单纯环形**（118dp 环、11dp 描边），分类名/剩余额/百分比全部在环内；数据 = 分类月预算 + 当月该分类支出，按剩余比例升序取最紧张的 4 个。
   - 模式③：中央两段大字——「本月已花」（颜色跟随剩余档位）与「总存款」（全部账户余额合计，负值转红），无环。
   - 顶部月份胶囊（显示态）+ 待确认徽标；底部圆点指示（当前项拉长为主色胶囊，点击可直达）。
2. **切换动效**：点击中心 = 页面横移 + 内容 0.93 收缩后带 spring 回弹的"弹动"（缩放只在 `graphicsLayer` draw 阶段读取，零重组）；滑动 = pager 跟手；圆点宽度/颜色 220ms 过渡。**颜色提醒**：三模式的额度色全部走 `animateColorAsState`(420ms)——绿(≥50%)/蓝(20–50%)/红(<20%) 档位切换时可见颜色渐变而非跳变。
3. **悬浮"记一笔"**（`ui/common/Components.kt` 的 `QuickAddPill`，AppNav Scaffold 的 FAB 槽在首页/账单页显示）：主色实心胶囊 + 8dp 阴影 + "＋ 记一笔"文字，1s 往返的轻微呼吸缩放提示"方便快速记账"，按压回弹；系统"减少动画"（ANIMATOR_DURATION_SCALE=0）时静态且模式切换瞬时。账单列表底部加 88dp 留白避免遮挡。首页原全宽按钮移除（入口统一到悬浮胶囊）。
4. **分类月预算**（模式②的数据前提）：
   - 存储：SharedPreferences `category_budget_<id>`（VM `categoryBudgets` StateFlow + `setCategoryBudget`，≤0 即清除；删除分类时同步清理）。
   - 入口：分类管理编辑弹窗（支出分类才显示"分类月预算（元，可留空）"字段），列表行右侧显示「月预算 ¥X」；设置页每月预算行副标题指向分类管理。
   - 测试：`CategoryRingsTest`（空预算/剩余与档位/未花过=全额/超支负值/按剩余升序取 4/收入与已删分类不参与）6 例。
5. **数据层**：`homeCategorySums`（当月各支出分类合计，口径与首页一致）、`totalDepositCents`（全部账户 初始金额+净额 合计）；`saveCategory` 回调携带保存后 id（新建分类可紧接着写预算）。

### 决策记录

- **首页仍是单文件**（`ui/home/HomeScreen.kt`）：三种模式 + 圆点 + 纯函数 `buildCategoryRings` 同文件；分页用标准 `HorizontalPager`，不引入新依赖。
- **不做自动轮播**：一切动画由用户交互触发，避免电量/误触/干扰；延续"动画不是数据真源"的教训（上轮粒子动画因卡顿整体回退，本轮只保留轻量过渡，连续动画只在 FAB 呼吸一处且仅 layer 缩放）。
- **模式②取舍**：按用户修正——环不带轨道与卡片底、文字在环内、加粗描边；百分比取整显示（超支显示 0%），环形弧长即剩余比例。
- **总存款口径** = 账户管理页余额合计（受"显示退款记录"开关影响，与账户页一致）。
