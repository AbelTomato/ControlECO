# 本地交易分类模型设计

## 目标

用已有本地标注支出交易训练轻量分类模型，向账单导入和捕获流程提供可回退的支出分类建议。收支方向由账单数据和用户确认决定，不由模型预测。

## 范围与约束

- 不读取或上传仓库外原始账单；已标注的 `统一训练候选.csv` 保持在本机，不加入 Git。
- 标签为“未知”的样本不进入训练；初版只训练支出分类，收入分类由现有规则处理。
- 初始候选为字符 n-gram + 逻辑回归；是否采用由分组留出集相对现有规则基线的结果决定。
- 分类标签直接使用支出分类名，包括自定义分类；应用只接受当前仍存在且类型为支出的分类。
- 多标签记录不参与单标签分类训练；“不计收支”不作为模型任务。
- 个性化继续使用现有 `MerchantRules`，用户明确确认/编辑捕获交易后更新商户分类规则；不另存个性化训练样本，不在线更新通用模型。
- 模型只产生支出分类建议。低置信度、分类缺失或推理失败时回退现有商户学习规则与关键词规则；不得改变交易方向或单独触发自动入账。
- 不引入网络调用。初始训练工具与模型文件均本地运行/存储。

## 当前训练数据基线

输入文件：`D:\AbelTomato_Files\Files\统一训练候选.csv`，位于仓库外。

- 当前统一数据集含 385 条支出、1 条收入、116 条不计收支；初版仅使用可用的支出单标签分类样本。
- 支出分类中多标签样本排除；收入和“不计收支”样本不用于初版模型。
- 标签长尾显著：最大类 230 条，最小若干类 1 至 3 条。
- 训练前必须按商户/规范化文本分组切分，报告支出分类 macro-F1、weighted-F1、准确率、类别召回率及样本数；极少样本类标记为不可可靠评估，不得以整体准确率掩盖。
- 若可评测样本不足或模型不优于现有规则基线，则保留离线实验结果，不接入产品流程。

## 架构

训练端优先评估字符 n-gram + 逻辑回归，使用可复现的分组留出评测；仅当它优于现有规则基线且指标有意义时才导出模型。模型只保存特征权重与标签，不含原始样本。Android 端通过独立纯 Kotlin 推理组件加载固定格式模型资产，输入去敏后的交易方/商品/备注文本，输出支出分类排序和分数。分类标签使用名称/稳定语义键，应用在使用结果前映射到当前支出分类。

- 个性化沿用当前 `MerchantRules` 的 Room 规则，不新增训练样本存储或基础模型重训。其键归一化、条数上限和分类存在性校验继续由现有实现负责；现有实现对匹配商户的后续确认/编辑会更新规则，不要求操作必须先改过分类。

## 接入与回退

- 分类调用顺序：现有商户学习规则优先；模型只在规则未命中时提供建议；模型低置信度或无有效分类时回退现有关键词/default 分类逻辑。用户在确认界面选择的分类始终优先。
- 收支方向由账单解析/通知规则及用户确认负责；模型不含方向预测头、不修改金额或方向。
- 只接受当前存在的支出分类，其他标签一律拒绝。
- 初期仅在导入预览/待确认界面展示或预选模型建议；自动入账必须经过独立验收和显式置信度门槛后才考虑。

## 隐私与安全

- 不保存账号、交易号、卡号、金额、精确时间、原始通知全文作为学习特征。
- 只使用归一化交易方、商品/简短备注；对数字串做脱敏。
- 不记录模型文本输入或完整用户样本到日志。
- 训练产物和个性化数据位于应用私有目录，不通过更新或网络传输。

## 验收标准

1. 可由指定本地 CSV 重现支出分类的离线训练，并导出不含训练原文的模型文件。
2. 训练排除“未知”、多标签、收入及“不计收支”样本。
3. 评测以文本/商户分组隔离训练与测试，输出支出分类各类别指标，并列出小样本不可评估类别。
4. Android 推理不依赖网络；未知标签、非支出/无当前分类、低置信度及损坏模型均安全回退。
5. 个性化只走现有 `MerchantRules`，不得新增模型样本持久化或在线训练。
6. 单元测试覆盖模型格式解析、分数/置信度、分类映射和回退。

## 非目标

- 不把公开网络数据加入当前训练集。
- 不使用云端 LLM 或服务端推理。
- 不让模型判定交易是否真实、解析金额/方向或直接执行入账。
- 不承诺在现有单用户小样本下长尾类别具有统计可靠性。
